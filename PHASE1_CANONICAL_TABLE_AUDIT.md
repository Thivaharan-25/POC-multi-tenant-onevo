## 4. Documented Extras (Developer Platform Extensions - now canonical)

`phase1-table-inventory.md`'s original 199-heading list omitted a set of Developer Platform tables that back real, already-built functionality (Demo Profile / Demo Request approval flow, subscription plan modules/add-ons/pricing). These tables are documented in `developer-platform/database/schema.md` and were required by `backend/CLAUDE.md`'s "ONEVO-HR coverage rule," but were never added as headings to `phase1-table-inventory.md` - a gap in that document, not a Phase 2 deferral (they do not appear in that file's "Excluded as Phase 2" list either).

An initial pass (2026-07-06) found 12 EF-mapped tables covering this functionality, all deviating from `schema.md`'s documented shape in some way. A follow-up review (same day, prompted by the requester questioning `module_feature_permissions`/`role_template_permissions`) found that several of these 12 were not just misnamed but structurally wrong - duplicate join-table modeling of relationships the canonical schema represents with a JSON/array column, or a global catalog where the canonical schema is per-plan. The EF model was reshaped table-by-table against `schema.md`, and the 7 survivors were added as real canonical headings to `phase1-table-inventory.md` (Section "Developer Platform Extensions") rather than kept as a documented-but-non-canonical allowlist. `VerifyPhase1SchemaExactlyMatchesInventory` now asserts `canonicalTables.Count == 206` and `extra == 0` with no allowlist.

**Disposition of the original 12:**

| Original Table | Disposition | Reason |
| :--- | :--- | :--- |
| `demo_profiles` | Kept, added missing `created_by_platform_user_id`/`updated_at` columns | Already matched `schema.md`'s `demo_profiles` closely. |
| `demo_profile_module_access` | Renamed to `demo_profile_modules`, added `feature_permissions` jsonb column | Matches canonical name; feature entitlements now live on the same row instead of a child table. |

| `demo_profile_upgrade_options` | Reshaped from a per-plan join table to one row per demo profile with `allowed_plan_ids`/`addon_visibility`/etc. jsonb columns | Canonical `demo_profile_upgrade_options` is 1:1 with `demo_profiles`, not a join table. |
| `demo_profile_allowed_add_ons` | **Removed** - merged into `demo_profile_upgrade_options.allowed_addon_module_keys`/`hidden_addon_module_keys`/`addon_visibility` (jsonb) | Not in `schema.md` at all; same anti-pattern as `demo_profile_feature_access`. |
